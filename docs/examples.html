Examples

Learn from a complete pipeline

Each example builds a host application with embedded native GLSL shaders. Its default execution path uses the CPU. Select a supported headless GPU profile to run the same pipeline on a GPU. Start with the buffer pipeline, then choose an operation close to your application.

# Build the examples and their embedded shaders in Release mode.
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
# Compile the configured applications and CPU adapters.
cmake --build build -j
# Run three linked stages on the CPU.
./build/example_pipeline
# Run the same application and shaders on an ES 3.1 GPU.
./build/example_pipeline --gpu es31

Supported profile arguments are es31, es32, gl43, gl45 and gl46. The driver supplies the requested GPU context. CPU examples use host resources. Each excerpt links to complete numbered source files.

Connect the complete pipeline. Keep each kernel alive while a stage refers to it. Read completed resources through a const reference. Use distinct writable resources for concurrent jobs and separate input and output storage for neighborhood filters.

Inspect an embedded GPU program

The export_shader utility exports an embedded GPU program for a chosen factory and profile. Use it to inspect the source passed to the driver or to check that program with a GLSL compiler. Application pipelines use the embedded programs directly.

# Export a registered native shader using the GLES 3.1 profile.
./build/export_shader affine_kernel es31 > affine.comp
# Validate the exported compute shader when glslangValidator is installed.
glslangValidator -S comp affine.comp

Read the exporter, the import and portability guide, and the public-source verification report.

Native kernel catalog

Every source below registers the filename stem followed by _kernel. The shared math kernel is used by the math parity checks. Some shaders are reused by several example applications.
